Xplayer is a free, local Electron music player for Windows. This repository is the development source tree; in the full project checkout, App/ contains generated/runtime output.

Current layout: electron/ owns the main process, preload/IPC, runtime scanner and metadata/download/lyrics/window services; build/ owns Python assembly and the HTML template; src/js/ is the renderer; src/css/ and src/assets/ hold renderer resources; tools/tests/ is the automated test suite and test support; .agent/ contains agent workflow, current plans and task reports.

Renderer files are ES modules. src/js/main.js is the single entry point and its import order is the load order. Modules are grouped under core/, api/, library/, playlists/, search/, playback/, lyrics/ and ui/ (including ui/subscribers/). Keep numeric prefixes. src/js/99-player.js is a build-time data template; core/build-data.js reads it. The deployed library comes from songs.json.

Runtime scanning belongs to electron/scan-folder.js; build/music_player.py assembles the application and does not scan audio. Electron uses nodeIntegration: false and contextIsolation: true; renderer/main communication goes through preload/contextBridge and IPC. Build output is App/MusicPlayerOutput/, launched via App/electron.exe.

For current architecture and folder details, read .agent/CONTEXT.md. Read .agent/AGENTS.md before changing files and claude.md for workflow/ownership guidance. Test commands, grouping, prerequisites and discovery are documented in tools/tests/README.md. Do not edit generated App output as the primary source.

Record detailed changes and verification in your own uniquely named report under .agent/reports/. Task agents must not edit the shared tools/CHANGELOG.md; the designated integration owner adds a concise entry after integration and verification. Never describe skipped or unrun checks as passing.
